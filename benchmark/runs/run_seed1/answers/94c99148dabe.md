## Answer

The component is `dropin/enrich_local.py` (`okfm.py enrich-local`), which drafts descriptions
against an Ollama instance you run yourself. It declares `needs: [model]` and sits in the
`level-3-enrich` bundle. Your premise is correct and the project agrees with it — it just is
not the premise the ladder is built on.

### The rule that blocks it is mechanical, and `model` is the whole of it

`dev/check_levels.py` hard-codes the ladder from DR-0008 and the per-level allowance:

```python
LADDER  = ["nothing", "human", "model", "secrets"]
ALLOWED = {1: set(), 2: {"human"}, 3: {"human", "model", "secrets"}}
```

It walks each bundle named in `LEVELS = {"level-1-view": 1, "level-2-build": 2,
"level-3-enrich": 3}`, reads the `needs-*` entries out of each concept's `tags:` line
(`needs_of`), and fails on `real - ALLOWED[level]`. A concept tagged `needs-model` inside the
level 2 bundle produces `needs ['model'], which level 2 does not allow (level 2 admits
['human'])`. There is no cost term anywhere in that script — money and API keys are not
inputs to it.

Note the asymmetry the docstring calls out: exposure is a **floor, not an equality**
(`needs ⊆ allowed(level)`), so a deterministic tool like `guard.py` is free to live at level 3.
The converse is what is forbidden — a `model`-declaring component cannot drop to level 2.

### Free-and-keyless is already a rung on the ladder, one step up

The four values are ordered by **exposure**, not price: `nothing < human < model < secrets`.
"Costs money / needs a key" is the `secrets` rung. "Something nondeterministic has to reason"
is the `model` rung. Local Ollama removes the first and keeps the second, so what it is, in
the vocabulary that already exists, is `needs-model` **without** `needs-secrets`.

DR-0013 makes exactly this point: that set has been legal since DR-0008 was written, and
`enrich_local.py` is simply the first thing OKFM ships that actually occupies it — *"the rung
stopped being hypothetical."* It does not need a new position on the ladder, because the
position it wants is the one it is already in.

### The stated principle: the ladder measures the ask, not the bill

From DR-0013: *"A level is what OKFM asks of you before you can start, not what it costs."*
Level 3's ask is *something has to reason*, and everything that follows from reasoning is
unchanged when the reasoning happens on your laptop — nondeterminism, output that must be
reviewed, `guard` checking what was written, and a human gate before promotion. DR-0009 makes
the 2→3 boundary *"deterministic vs. reasoning — the sharpest line in the project."*

DR-0009's own amendment ran the same argument in the other direction to retire level 4: holding
the key yourself is a change of *direction*, not a step up. DR-0013 notes it is that argument
run backwards and landing in the same place.

### Why the rule is not simply loosened

Two reasons given explicitly in DR-0013:

1. Putting a model-calling component at level 2 either breaks the check or forces it to be
   rewritten around "key / no key" — and *"a rule loosened to admit the first thing that did
   not fit is no longer a rule."*
2. The check is the only thing keeping level 2's promise honest as the code grows. `README.md`
   and `docs/okfm-guide/README.md` both sell it as a *checked property* rather than a promise:
   *"level 2 never needs a model"* is true because `check_levels.py` fails the build otherwise.

DR-0013's amendment prices the alternative precisely: moving it for real means `ALLOWED[2]` in
`dev/check_levels.py` gains `model`, the level 2 bundle takes the concept, and the promise that
nothing at level 2 requires a model stops being true. *"That is the trade, and it is not being
made — the check is the only thing keeping the promise honest as the implementation grows, and
a name is not worth spending it."*

### What you did get: the name **Level 2+**

Your objection was accepted on the axis it is actually about. The 2026-08-02 amendment to
DR-0013 (made by the steward, over that record's original argument, and recorded rather than
quietly applied) renamed it **Level 2+**, because *"Level 3, local variant"* described the
machinery correctly and told an adopter nothing about what it would cost them.

The resolution is two axes: **the ladder measures what OKFM asks of you before you can start;
the name measures what it costs you.** Those were the same number for as long as a model meant
an API key; this is the first thing that pulled them apart. The `+` is described as
load-bearing — it is *not* level 2, because pretending so would make level 2's "never needs a
model" false; it is level 2's terms plus something you supply.

The amendment table lists exactly what the rename does not touch: `enrich_local.py` still
declares `needs: [model]`, it still lives in the `level-3-enrich` bundle, `dev/check_levels.py`
is unchanged with `ALLOWED[2]` still admitting only `human`, and the 2/3 boundary is still
exactly the `model` line. `okfm.json`'s `_enrich` comment and `README.md`'s level table both
carry the "2+" name over the unchanged mechanics.

### A second, separate constraint worth not confusing with the first

Even inside level 3, `enrich-local` is deliberately absent from `STEPS` in `dropin/okfm.py` —
it lives in `EXTRA` instead. That is the DR-0008 union rule: a workflow's `needs` is the union
of everything it invokes, and the fork-PR CI job admits only `needs ⊆ {}`, so listing it in
the pipeline would take the whole default run out of CI. The folder's promise narrows from
*every component here is `needs: []`* to *every component the pipeline runs is `needs: []`*.

### Related: there is no "free network" rung either

DR-0008 rejected a fifth `network` value on the grounds that nothing needed the open internet
without a credential. DR-0013 upholds that — loopback is not the open internet — but records
the re-entry trigger as concrete: point `enrich.base_url` at a public host with no key and the
rejected fifth value is exactly what would describe it. That is why the local/credentialed line
is written down in machine-readable form: `dropin/config_schema.py` checks
`urlsplit(base_url).hostname` against `LOOPBACK = ("localhost", "127.0.0.1", "::1", "0.0.0.0")`
and emits a `warn` finding when it is not loopback — *"a distinction nothing checks decays into
a distinction nothing means."*

(Note: `check_levels.py` reads generated bundles under `.okfm/`, which is not present in this
snapshot — the `needs-*` tags it inspects live on the built concepts, not on the `docs/` source
files, which carry no frontmatter.)
